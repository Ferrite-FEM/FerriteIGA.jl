Getting started

FerriteIGA is designed such that an isogeometric program looks, as far as possible, like a standard Ferrite program. This page lists the (few) places where an isogeometric program differs from a Ferrite program. It assumes that you are familiar with Ferrite, for example through the first Ferrite tutorial, Heat equation.

From Ferrite to FerriteIGA

The table below summarizes the differences between a Ferrite program and a FerriteIGA program. Everything that is not listed, such as the DofHandler, the ConstraintHandler, the assembler, the element routine and the linear solve, is exactly the same.

StepFerriteFerriteIGA
Load the packageusing Ferriteusing FerriteIGA (re-exports Ferrite)
Geometrygenerate_grid(Quadrilateral, nels)generate_nurbs_patch(:name, nels, order), a NURBSMesh
Grida GridBezierGrid(mesh), a BezierGrid
InterpolationLagrange{RefQuadrilateral, order}()IGAInterpolation{RefQuadrilateral, order}()
Cell valuesCellValues(qr, ip)BezierCellValues(qr, ip)
Facet valuesFacetValues(fqr, ip)BezierFacetValues(fqr, ip)
Cell coordinatesgetcoordinates(grid, cellid) returns a vector of nodesreturns a BezierCoords
Cell loopfor cell in CellIterator(dh)for cellid in 1:getncells(grid) or an IGACellCache
ExportVTKGridFile(name, grid)VTKIGAFile(name, grid)

The main conceptual difference is in the first two steps. In standard finite elements the mesh is an approximation of the geometry, and the nodes lie on it. In isogeometric analysis the geometry is a spline patch, described by knot vectors, control points and weights. The patch is converted to a BezierGrid, where the nodes are the control points and the cells are the knot spans. Each cell also stores a Bézier extraction operator, which BezierCellValues uses to evaluate the spline basis functions. All of this happens behind the scenes, and is explained in the topic guides.
